Версия 2.0 · 25.11.2026 · Órleu Hack 2026, кейс 3 «Образование: читать и понимать»

## 1. Продукт

PWA для учеников 7–9 классов. Ученик читает короткий текст и сам формулирует к нему вопросы. ИИ классифицирует каждый вопрос по уровню понимания (4 уровня, привязаны к навыкам чтения PISA) и начисляет очки. Учитель видит прогресс класса в веб-панели.

Требование кейса: решение работает в сельской школе **со слабым интернетом**. Проектируем под медленную и нестабильную связь; при полном отсутствии связи приложение деградирует, но не ломается (раздел 8).

Ограничения:

- Языки интерфейса и контента: **kk**, **ru**.
- Целевое устройство: дешёвый Android, Chrome, экран от 360 px.
- Claude вызывается **только с сервера**. Ключ API на клиенте запрещён.

│ frontend (PWA)       │ ────────────────► │ VPS: 2 vCPU / 4 GB / 50 GB NVMe       │ ────────► │ Claude API │

- Caddy отдаёт собранный фронтенд (`frontend/dist`) и проксирует `/api/*` в `api`.
- Фронтенд и API на одном домене — CORS не нужен.
- PostgreSQL не публикуется наружу.
- HTTPS обязателен: без него не работает Service Worker (PWA). Без своего домена — `<ip-с-дефисами>.sslip.io`.

## 6. Модель данных (PostgreSQL, EF Core)

Все `Id` — `Guid`. `Session.Id` и `Question.Id` генерирует клиент (`crypto.randomUUID()`), чтобы повторная отправка была идемпотентной.

| Таблица | Поля |
|---|---|
| `teachers` | `id`, `email` (unique), `password_hash`, `name`, `school`, `created_at` |
| `classes` | `id`, `teacher_id` → teachers, `name` («8А»), `join_code` (unique, «8A-4821»), `lang` (`kk`/`ru`), `created_at` |
| `students` | `id`, `class_id` → classes, `name` (только имя), `device_token_hash` (SHA-256), `interests` (text[]), `points`, `streak`, `last_active_date`, `created_at` |
| `texts` | `id`, `lang`, `topic`, `kind`, `difficulty` (1–5), `title`, `body` (markdown, 150–300 слов), `example_questions` (jsonb: уровень → вопрос), `hints` (jsonb), `reviewed` (bool), `updated_at` |
| `sessions` | `id`, `student_id`, `text_id`, `conclusion`, `conclusion_score` (0–20), `points`, `started_at`, `finished_at`, `received_at` |
| `questions` | `id`, `session_id`, `position` (1–3), `body`, `level_local` (0–4), `level_ai` (0–4, null = не оценено), `ai_comment`, `ai_hint`, `level_teacher` (null), `created_at` |

Справочники:

- `topic`: `sport`, `games`, `money`, `nature`, `history`, `tech`, `local`
- `kind`: `article`, `table`, `notice`, `schedule`, `social_post`, `math_problem`

Итоговый уровень вопроса: `level_teacher ?? level_ai ?? level_local`.

Доступ: учитель видит только свои классы (фильтр по `teacher_id` из JWT в каждом запросе). Ученик видит только свои данные (по токену устройства).

## 7. API

Базовый путь `/api`. JSON, `camelCase`. Ошибки — `ProblemDetails` (RFC 9457).

Авторизация:

- Учитель: `Authorization: Bearer <jwt>`, срок жизни 7 дней.
- Ученик: `X-Device-Token: <token>`; сервер сравнивает SHA-256 токена с `students.device_token_hash`.

### 7.1 Ученик

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/student/join` | `{ joinCode, name, lang }` → `{ studentId, deviceToken, className }`. 404 — код не найден |
| GET | `/api/student/me` | `{ name, points, rank, streak }` |
| GET | `/api/student/pack?lang=kk&since=<iso>` | Тексты с `reviewed = true` и `updated_at > since` → `{ version, texts[] }` |
| POST | `/api/student/sessions` | Upsert пачки сессий (≤ 20) + оценка Claude. Ответ ниже |

`POST /api/student/sessions`:

```json
// request
{
  "sessions": [{
    "id": "uuid", "textId": "uuid",
    "startedAt": "2026-11-26T10:00:00Z", "finishedAt": "2026-11-26T10:07:00Z",
    "conclusion": "string | null",
    "questions": [{ "id": "uuid", "position": 1, "body": "string", "levelLocal": 2, "createdAt": "..." }]
  }]
}
// response 200
{
  "graded": [{ "questionId": "uuid", "level": 3, "comment": "string", "hint": "string" }],
  "sessions": [{ "id": "uuid", "points": 95, "conclusionScore": 15 }],
  "student": { "points": 640, "rank": "detective", "streak": 4 }
}
```

- Повторная отправка той же сессии не создаёт дублей и не меняет уже оценённые вопросы.
- Claude недоступен или превысил 6 с → сессии сохраняются, `graded` возвращается частично или пустым; неоценённые вопросы оцениваются при следующем вызове.

## 8. Работа при слабом интернете

| Состояние сети | Поведение |
|---|---|
| Нормальная | Вопросы отправляются сразу после сессии, Claude оценивает за 1–3 с |
| Слабая | Клиент ждёт ответ ≤ 8 с. Не дождался → показывает предварительную оценку правилами, сессия остаётся в очереди |
| Нет связи | Приложение открывается из кеша, тексты из IndexedDB, оценка правилами, очередь копится |

Клиент:

1. Service Worker кеширует оболочку приложения (precache). Первая загрузка ≤ 2 МБ.
2. Пакет текстов хранится в Dexie, обновляется по `since` (только новое).
3. Завершённая сессия пишется в `outbox` до отправки.
4. Отправка очереди: при завершении сессии, при событии `online`, при открытии приложения. Повтор с экспоненциальной задержкой: 5 с, 15 с, 60 с, затем раз в 5 мин.
5. После ответа сервера оценки Claude заменяют предварительные, очки пересчитываются, запись удаляется из `outbox`.

Таблицы Dexie:

```ts
db.version(1).stores({
  texts:     'id, lang, difficulty, topic',
  sessions:  'id, textId, finishedAt',
  questions: 'id, sessionId',
  outbox:    '++seq, sessionId',
  meta:      'key'   // studentId, deviceToken, packVersion, points, streak
});
```

## 9. Оценка вопросов

### 9.1 Уровни

| Уровень | Код | Критерий | Очки |
|---|---|---|---|
| 0 | `off_text` | Не связан с текстом, повтор, бессмыслица | 0 |
| 1 | `locate` | Ответ прямо есть в тексте | 10 |
| 2 | `connect` | Нужно связать 2+ факта из текста | 20 |
| 3 | `infer` | Ответа в тексте нет, нужен вывод | 30 |
| 4 | `evaluate` | Оценка достоверности, позиции автора, качества аргумента | 50 |

Вывод (conclusion): 0–20 очков.

### 9.2 Claude (`Services/Grading/ClaudeGradingService.cs`)

- Модель `claude-haiku-5-5`, structured outputs (`output_config.format`, JSON-схема ниже).
- Один запрос на сессию: текст + 3 вопроса + вывод.
- Системный промпт на языке текста (kk/ru): определения уровней из 9.1 и по 2 примера на уровень. Промпты хранятся в `Services/Grading/Prompts/`.
- Claude не отвечает на вопросы ученика и не даёт готовых ответов. Только уровень, комментарий (≤ 25 слов, на «ты», доброжелательно) и подсказка, как спросить глубже.
- Таймаут запроса к Claude — 6 с, 1 повтор.

```json
{
  "questions": [{ "position": 1, "level": 3, "comment": "string", "hint": "string" }],
  "conclusionScore": 15,
  "conclusionComment": "string"
}
```

### 9.3 Правила на устройстве (`frontend/src/scoring/heuristic.ts`)

Используются только когда ответа Claude нет. Тот же алгоритм дублируется на сервере в `HeuristicGrader` для `level_local`, если клиент его не прислал.

1. Меньше 3 слов или совпадение с предыдущим вопросом сессии → 0.
2. Нет ни одного слова длиной ≥ 4 из текста → 0.
3. Маркеры (регистр игнорируется, сравнение по началу слова), приоритет от 4 к 1:

| Уровень | ru | kk |
|---|---|---|
| 4 | можно ли доверять, прав ли, докажи, достоверн, убедительн | сенуге бола ма, дұрыс па, дәлелде, сенімді |
| 3 | что будет, если, как думаешь, успеет ли, хватит ли, что было бы | егер, қалай ойлайсың, үлгере ме, жете ме, не болар еді |
| 2 | почему, зачем, чем отличается, как связан | неліктен, неге, не үшін, айырмашылығы |
| 1 | кто, где, когда, сколько, что, какой | кім, қайда, қашан, қанша, не, қандай |

Нет маркеров → 1.

## 10. Очки, ранги, стрик (`Services/Scoring/PointsCalculator.cs`)

Очки сессии = сумма очков вопросов по итоговому уровню + `conclusion_score`. Очки ученика = сумма очков его сессий (пересчитываются при оценке Claude и правке учителя).

| Ранг | Код | Очки от |
|---|---|---|
| Новичок | `novice` | 0 |
| Сыщик | `sleuth` | 200 |
| Детектив | `detective` | 600 |
| Профессор | `professor` | 1500 |
| Мастер вопросов | `master` | 3000 |

Стрик: +1 за календарный день (`Asia/Almaty`) с ≥ 1 завершённой сессией; пропуск дня → 1. Источник истины — сервер; клиент показывает локальный расчёт до синхронизации.

## 11. Аналитика учителя

| Метрика | Формула |
|---|---|
| Уровень класса | Средний итоговый уровень вопросов за 7 дней |
| Карта навыков | Доля вопросов уровней 0–4 за 7 / 28 дней |
| Глубина | Доля вопросов уровней 3–4 по неделям |
| Активность | Ученики с сессией за 7 дней / все ученики |

Сигналы (T5):

| Сигнал | Условие |
|---|---|
| `stuck` | ≥ 5 сессий за 14 дней и 0 вопросов уровня ≥ 3 |
| `inactive` | Нет сессий 7 дней |
| `rising` | Доля уровней 3–4 за 7 дней выше, чем за предыдущие 7, на ≥ 20 п.п. |

## 12. Генерация контента (`Services/Content`)

- Запуск: `dotnet run --project backend -- generate-texts --lang kk --topic local --kind schedule --difficulty 2 --count 5`.
- Модель `claude-opus-5-5`, structured outputs, схема = поля `texts`.
- Требования: 150–300 слов, реалии Казахстана, без выдуманных фактов о реальных людях и организациях, интересно подростку 13–15 лет.
- Записывается с `reviewed = false`. Публикация после проверки человеком (kk — носитель языка).

## 13. Деплой

Сервер: VPS 2 vCPU / 4 GB RAM / 50 GB NVMe, Ubuntu 22.04+, Docker + Compose.

| Сервис | Образ | Порты |
|---|---|---|
| `caddy` | `caddy:2` | 80, 443 наружу |

4. Миграции применяются при старте `api` (`Database.Migrate()`).

Безопасность: открыты только 22, 80, 443 (ufw). Секреты только в `backend/deploy/.env` на сервере, файл в `.gitignore`.

## 17. Критерии приёмки MVP

- [ ] Ученик входит по коду класса, выбирает язык.

- [ ] Учитель меняет уровень вопроса — очки ученика пересчитываются.
- [ ] В БД ≥ 20 проверенных текстов, из них ≥ 10 на казахском.
- [ ] `PointsCalculator` и `HeuristicGrader` покрыты тестами.
- [ ] Ключи отсутствуют в git и в бандле клиента.
- [ ] Демо открывается по HTTPS-ссылке с телефона без установки.
