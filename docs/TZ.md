## 1. Продукт

PWA для учеников 7–9 классов. Ученик читает короткий текст и сам формулирует к нему вопросы. ИИ классифицирует каждый вопрос по уровню понимания (4 уровня, привязаны к навыкам чтения PISA) и начисляет очки. Учитель видит прогресс класса в веб-панели.

Требование кейса: решение работает в сельской школе **со слабым интернетом**. Проектируем под медленную и нестабильную связь; при полном отсутствии связи приложение деградирует, но не ломается (раздел 8).

Ограничения:

- Языки интерфейса и контента: **kk**, **ru**.
- Целевое устройство: дешёвый Android, Chrome, экран от 360 px. Связь — вплоть до 2G/EDGE.
- Одно устройство могут использовать несколько учеников (семейный телефон, компьютерный класс). Данные и очередь отправки каждого ученика хранятся отдельно.
- ИИ (OpenAI) вызывается **только с сервера**. Ключ API на клиенте запрещён.

## 3. Архитектура

```
┌──────────────────────┐   HTTPS / JSON    ┌──────────────────────────────────────┐   HTTPS   ┌────────────┐
│ frontend (PWA)       │ ────────────────► │ VPS: 2 vCPU / 4 GB / 50 GB NVMe       │ ────────► │ Groq API   │
│ React + Vite + TS    │                   │  caddy      :443  TLS, статика фронта │           └────────────┘
│ Service Worker кеш   │ ◄──────────────── │  api        :8080 ASP.NET Core .NET 9 │
│ IndexedDB (Dexie)    │                   │  postgres   :5432 только внутр. сеть  │
│ outbox + эвристика   │                   └──────────────────────────────────────┘
└──────────────────────┘
```

- Caddy отдаёт собранный фронтенд (`frontend/dist`) и проксирует `/api/*` в `api`.
- Фронтенд и API на одном домене — CORS не нужен.
- PostgreSQL не публикуется наружу.
- HTTPS обязателен: без него не работает Service Worker (PWA). Без своего домена — `<ip-с-дефисами>.sslip.io`.

## 6. Модель данных (PostgreSQL, EF Core)

Все `Id` — `Guid`. `Session.Id` и `Question.Id` генерирует клиент (`crypto.randomUUID()`), чтобы повторная отправка была идемпотентной.

| Таблица | Поля |
|---|---|
| `users` | `id`, `email` (unique, **null у учеников**), `password_hash` (BCrypt; у ученика — хеш PIN), `name`, `role` (`Student` / `Teacher` / `Admin`), `failed_logins`, `locked_until`, `created_at` |
| `classes` | `id`, `teacher_id` → users, `name` («8А»), `join_code` (unique, «8A-4821»), `lang` (`kk`/`ru`), `created_at` |
| `students` | `id`, `user_id` → users (unique, 1:1), `class_id` → classes (null только у старых учётных записей с email и у убранных из класса), `interests` (text[], в MVP не используется), `points`, `streak`, `last_active_date`, `created_at`. Имя ученика — `users.name`, уникально в классе без учёта регистра («Айгерим Б.») |
| `diagnostics` | `id`, `student_id`, `kind` (`pre` / `post`), `score` (0–6), `answers` (jsonb), `taken_at` — раздел 11.1 |
| `texts` | `id`, `class_id` → classes (null — общая библиотека), `created_by_id` → users, `lang`, `topic`, `kind`, `difficulty` (1–5), `title`, `body` (markdown, 150–300 слов), `example_questions` (jsonb: уровень → вопрос), `hints` (jsonb), `reviewed` (bool — опубликован для учеников класса), `updated_at` |
| `sessions` | `id`, `student_id`, `text_id`, `conclusion`, `conclusion_score` (0–20), `points`, `started_at`, `finished_at`, `received_at` |
| `questions` | `id`, `session_id`, `position` (1–3), `body`, `level_local` (0–4), `level_ai` (0–4, null = не оценено), `ai_comment`, `ai_hint`, `level_teacher` (null), `created_at` |

Справочники:

- `topic`: `sport`, `games`, `money`, `nature`, `history`, `tech`, `local`
- `kind`: `article`, `table`, `notice`, `schedule`, `social_post`, `math_problem`

Итоговый уровень вопроса: `level_teacher ?? level_ai ?? level_local`.

Роли:

| Роль | Как появляется | Доступ |
|---|---|---|
| `student` | Вход по коду класса: вводит имя и придумывает PIN → создаются `users` (без email) + `students` уже в классе | Только свои данные |
| `teacher` | Регистрация с выбором «Я учитель» | Только свои классы и их тексты (фильтр по `teacher_id` из JWT). Отвечает за тексты своего класса: публикует их сам. Читает общую библиотеку |
| `admin` | Не регистрируется через форму. Создаётся при старте API из настроек `Admin:Email` / `Admin:Password` | Только наблюдает: сводка, списки учителей, учеников, классов. Тексты не проверяет и не правит |

## 7. API

Базовый путь `/api`. JSON, `camelCase`. Ошибки — `ProblemDetails` (RFC 9457).

Авторизация для всех ролей: `Authorization: Bearer <jwt>`, срок жизни 7 дней. Claims: `sub` (id), `email`, `name`, `role` (`student` / `teacher` / `admin`). Доступ по роли — `RequireAuthorization(p => p.RequireRole("teacher"))`.

### 7.0 Авторизация (этап 1, готово)

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/auth/register` | `{ name, email, password, role: "student" \| "teacher" }` → `{ token, user }`. 400 — ошибки полей (`errors.name/email/password/role`), email занят |
| POST | `/api/auth/login` | `{ email, password }` → `{ token, user }`. 401 — неверный email или пароль |
| GET | `/api/auth/me` | `user` = `{ id, name, email, role }`. 401 — без токена |

Правила: email приводится к нижнему регистру; пароль ≥ 8 символов; имя 2–80 символов; роль `admin` через регистрацию запрещена.

### 7.0.1 Вход ученика без email (этап 2б, A2)

Регистрация через `/api/auth/register` остаётся только для учителя (`role: "student"` → 400). Ученик не вводит email и пароль.

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/auth/student/class` | `{ joinCode }` → `{ className, students: [{ id, displayName }] }` — список имён класса для выбора. 404 — код не найден |
| POST | `/api/auth/student/register` | `{ joinCode, displayName, pin }` → `{ token, user }`. 400 — имя занято в классе («добавь первую букву фамилии»), PIN не из 4 цифр |
| POST | `/api/auth/student/login` | `{ joinCode, studentId, pin }` → `{ token, user }`. 401 — неверный PIN |
| POST | `/api/classes/{id}/students/{studentId}/reset-pin` | Только учитель класса → `{ pin }` — новый временный PIN |

- PIN — 4 цифры, хранится как BCrypt-хеш. После 5 неверных попыток вход ученика блокируется на 10 минут (`locked_until`), учитель может сбросить PIN.
- В JWT ученика `email` не пишется. `user.email` в ответах — `null`.
- `POST /api/student/join-class` остаётся для учётных записей, созданных до версии 2.2; новый поток его не использует.

### 7.0.2 Несколько учеников на устройстве (A3)

- На устройстве хранится список профилей `{ studentId, displayName, className, token }` (Dexie, таблица `profiles`).
- При открытии приложения с ≥ 2 профилями — экран «Кто занимается?»; выбор профиля спрашивает PIN, если с последнего входа прошло > 30 минут (PIN проверяется по локальному хешу, сеть не нужна).
- Сессии, вопросы и очередь отправки привязаны к `studentId`. Очередь каждого ученика отправляется с его токеном, даже если сейчас выбран другой ученик.
- «Выйти» удаляет профиль с устройства только после того, как его очередь пуста; иначе — предупреждение.

## 8. Работа при слабом интернете

| Состояние сети | Поведение |
|---|---|
| Нормальная | Вопросы отправляются сразу после сессии, ИИ оценивает за 1–3 с |
| Слабая | Клиент ждёт ответ ≤ 8 с. Не дождался → показывает предварительную оценку правилами, сессия остаётся в очереди |
| Нет связи | Приложение открывается из кеша, тексты из IndexedDB, оценка правилами, очередь копится |

Клиент:

1. Service Worker кеширует оболочку приложения (precache). Первая загрузка ученика ≤ 500 КБ JS+CSS (gzip): страницы учителя, админа и Recharts — отдельными чанками, в precache ученика не входят.
2. Пакет текстов хранится в Dexie, обновляется по `since` (только новое).
3. Завершённая сессия пишется в `outbox` до отправки, с `studentId` (раздел 7.0.2).
4. Отправка очереди: при завершении сессии, при событии `online`, при открытии приложения — для всех профилей устройства, каждый со своим токеном. Повтор с экспоненциальной задержкой: 5 с, 15 с, 60 с, затем раз в 5 мин.
5. После ответа сервера оценки ИИ заменяют предварительные, очки пересчитываются, запись удаляется из `outbox`.

Таблицы Dexie:

```ts
db.version(1).stores({
  profiles:  'studentId',                        // displayName, className, token, pinHash, lastUnlockAt
  texts:     'id, lang, difficulty, topic',
  sessions:  'id, studentId, textId, finishedAt',
  questions: 'id, sessionId',
  outbox:    '++seq, studentId, sessionId',
  meta:      'key'   // packVersion; очки и стрик — по ключу `progress:<studentId>`
});
```

## 9. Оценка вопросов

### 9.1 Уровни

| Уровень | Код | Критерий | Очки |
|---|---|---|---|
| 0 | `off_text` | Не связан с текстом, повтор, бессмыслица | 0 |
| 1 | `locate` | Ответ прямо есть в тексте | 10 |
| 2 | `connect` | Нужно связать 2+ факта из текста | 20 |
| 3 | `infer` | Ответа в тексте нет, нужен вывод | 30 |
| 4 | `evaluate` | Оценка достоверности, позиции автора, качества аргумента | 50 |

Вывод (conclusion): 0–20 очков.

### 9.2 ИИ (`Services/Grading/OpenAiGradingService.cs`)

- Модель `openai/gpt-oss-20b` (`OpenAI:GradingModel`), Structured Outputs (строгая JSON-схема ниже).
- Один запрос на сессию: текст + 3 вопроса + вывод.
- Системный промпт на языке текста (kk/ru): определения уровней из 9.1 и по 2 примера на уровень. Промпты хранятся в `Services/Grading/Prompts/`.
- ИИ не отвечает на вопросы ученика и не даёт готовых ответов. Только уровень, комментарий (≤ 25 слов, на «ты», доброжелательно) и подсказка, как спросить глубже.
- Общий бюджет на оценку сессии — **6,5 с**, включая повтор: первая попытка с таймаутом 4 с, повтор — только если осталось ≥ 2 с, с таймаутом на остаток. Так сервер всегда отвечает раньше, чем клиент перестаёт ждать (8 с).

```json
{
  "questions": [{ "position": 1, "level": 3, "comment": "string", "hint": "string" }],
  "conclusionScore": 15,
  "conclusionComment": "string"
}
```

### 9.3 Правила на устройстве (`frontend/src/scoring/heuristic.ts`)

Используются только когда ответа ИИ нет. Тот же алгоритм дублируется на сервере в `HeuristicGrader` для `level_local`, если клиент его не прислал.

Правила дают **только предварительную** оценку и намеренно осторожны: их легко обмануть, если начать вопрос с маркера («Можно ли доверять тексту?» без опоры на текст). Поэтому офлайн-оценка **не выше уровня 2**, а уровни 3–4 ставит только ИИ на сервере или учитель.

1. Меньше 4 слов или совпадение с предыдущим вопросом сессии (после нормализации: нижний регистр, без знаков препинания) → 0.
2. Нет ни одного слова длиной ≥ 4 из текста (сравнение по первым 5 буквам — грубая замена основы для kk и ru) → 0.
3. Маркеры (регистр игнорируется):

| Уровень | ru | kk |
|---|---|---|
| 2 | почему, зачем, чем отличается, как связан, что будет, если, как думаешь, можно ли доверять, прав ли, докажи | неліктен, неге, не үшін, айырмашылығы, егер, қалай ойлайсың, сенуге бола ма, дұрыс па, дәлелде |
| 1 | кто, где, когда, сколько, что, какой | кім, қайда, қашан, қанша, не, қандай |

- Однословные маркеры сравниваются **целым словом**, а не по началу: «что» не совпадает с «чтобы», kk «не» — с «негізгі», «неше».
- Маркеры из нескольких слов («можно ли доверять», «сенуге бола ма») ищутся как фраза.
- Маркер уровня 2 засчитывается, только если в вопросе есть ≥ 2 разных слов из текста (правило 2 — для одного слова). Иначе → 1.

Нет маркеров → 1.

На экране итога предварительная оценка показывается серым с подписью «Предварительно — ИИ проверит, когда появится интернет». Если ИИ поставил выше — ученик видит «Вопрос оказался глубже, +N очков».

### 9.4 Проверка качества оценки (Q2)

- Набор `backend/tests/grading-eval/` — 40 вопросов к 6 текстам (20 kk, 20 ru), по 8 на каждый уровень 0–4. Уровень ставит учитель команды; для kk — носитель языка.
- Команда `dotnet run --project backend -- eval-grading` прогоняет набор через `OpenAiGradingService` и `HeuristicGrader` и печатает: точное совпадение с учителем, совпадение ±1 уровень, матрицу ошибок, отдельно по kk и ru.
- Цель: точное совпадение ИИ ≥ 70%, ±1 ≥ 90% по каждому языку. Если kk ниже — дорабатываем промпт (больше примеров на казахском) до 26.11 23:00.
- Цифры идут на слайд: «ИИ совпадает с учителем в X% случаев».

## 10. Очки, ранги, стрик (`Services/Scoring/PointsCalculator.cs`)

Очки сессии = сумма очков вопросов по итоговому уровню + `conclusion_score`. Очки ученика = сумма очков его сессий (пересчитываются при оценке ИИ и правке учителя).

Очки сессии, где есть хотя бы один вопрос без `level_ai` и `level_teacher`, — **предварительные**: на главной показываются отдельно («+40 ждут проверки») и не входят в ранг и рейтинг. Так очки никогда не отнимаются после синхронизации.

| Ранг | Код | Очки от |
|---|---|---|
| Новичок | `novice` | 0 |
| Сыщик | `sleuth` | 200 |
| Детектив | `detective` | 600 |
| Профессор | `professor` | 1500 |
| Мастер вопросов | `master` | 3000 |

Стрик (S9, если успеваем): +1 за календарный день (`Asia/Almaty`) с ≥ 1 завершённой сессией; пропуск дня → 1. Источник истины — сервер; клиент показывает локальный расчёт до синхронизации.

## 11. Аналитика учителя

| Метрика | Формула |
|---|---|
| Уровень класса | Средний итоговый уровень вопросов за 7 дней |
| Карта навыков | Доля вопросов уровней 0–4 за 7 дней (28 дней — T8, если успеваем) |
| Глубина | Доля вопросов уровней 3–4 по неделям |
| Активность | Ученики с сессией за 7 дней / все ученики |
| Рост глубины | Доля вопросов уровней 3–4 в первых 3 сессиях ученика против последних 3 — главная метрика для питча |
| Диагностика | Средний балл `pre` и `post` по классу (раздел 11.1) |

Сигналы (T5):

| Сигнал | Условие |
|---|---|
| `stuck` | ≥ 5 сессий за 14 дней и 0 вопросов уровня ≥ 3 |
| `inactive` | Нет сессий 7 дней |
| `rising` | Доля уровней 3–4 за 7 дней выше, чем за предыдущие 7, на ≥ 20 п.п. |

### 11.1 Мини-диагностика (Q1)

Отвечает на вопрос жюри «как вы знаете, что грамотность растёт», а не только что приложение работает.

- Две параллельные формы A и B: по 2 коротких текста (kk и ru версии), 6 заданий формата PISA — 2 «найти информацию», 2 «понять и связать», 2 «оценить и поразмышлять». Задания с выбором ответа, проверяются на устройстве, работают офлайн.
- Задания пишет команда и проверяет учитель (не публикуем непроверенный текст ИИ).
- `pre` — при первом входе ученика (форма A или B случайно), `post` — после 10 сессий или по кнопке учителя (вторая форма). Результат уходит через ту же очередь отправки.
- Пилот 26.11 на 5–10 школьниках: `pre` → 3–4 сессии → `post` + опрос. За один день рост балла может не проявиться, поэтому на слайд идут и диагностика, и «Рост глубины» вопросов по сессиям — честно как пилот, с числом учеников.

## 12. Генерация контента (`Services/Content`)

- Учитель: кнопка «ИИ» в разделе «Тексты» класса (`POST /api/classes/{id}/texts/generate`, до 5 текстов) → черновики класса.
- Общая библиотека (`class_id = null`) пополняется командой: `dotnet run --project backend -- generate-texts --lang kk --topic local --kind schedule --difficulty 2 --count 5`.
- Модель `openai/gpt-oss-120b` (`OpenAI:TextModel`), Structured Outputs, схема = поля `texts`. Qwen на Groq strict-схему не выдерживает (проверено 25.11).
- Требования: 180–300 слов, реалии Казахстана, без выдуманных фактов о реальных людях и организациях, интересно подростку 13–15 лет.
- Всё сгенерированное — черновик (`reviewed = false`). Публикует учитель класса после прочтения: он отвечает за тексты своих учеников.
- Каждый текст должен давать материал для вопросов уровня 4: есть мнение, реклама, спорное утверждение или неполные данные (особенно у `social_post`, `notice`).

## 13. Деплой

Сервер: VPS 2 vCPU / 4 GB RAM / 50 GB NVMe, Ubuntu 22.04+, Docker + Compose. Пошагово — `backend/deploy/README.md`.

| Сервис | Образ | Порты |
|---|---|---|
| `caddy` | сборка из `frontend/Dockerfile`: Node 22 собирает PWA → `caddy:2-alpine` отдаёт её | 80, 443 наружу |
| `api` | сборка из `backend/Dockerfile` (`dotnet/aspnet:9.0`) | 8080, только внутренняя сеть |
| `postgres` | `postgres:17` | 5432, только внутренняя сеть; том `pgdata` |

Порядок:

1. Склонировать репозиторий на сервер, заполнить `backend/deploy/.env` по `backend/deploy/.env.example`. Node на сервере не нужен: фронтенд собирается в Docker.
2. `docker compose -f backend/deploy/docker-compose.yml up -d --build`
3. Миграции применяются при старте `api` (`Database.MigrateAsync()` в `Program.cs`, до CLI-команд).
4. Библиотека текстов: `export-texts` там, где она есть → `import-texts` на сервере (дубли по языку и заголовку пропускаются), или `generate-texts` на сервере. Затем `seed-demo`.

Caddy (`backend/deploy/Caddyfile`): HTTPS от Let's Encrypt, `encode zstd gzip`, `/api/*` и `/health` → `api:8080`, остальное — PWA с откатом на `index.html`. Кеш: `/assets/*` — `immutable` на год, остальное (`index.html`, `sw.js`, манифест) — `no-cache`, чтобы новая версия доходила до учеников.

API за прокси: адрес клиента берётся из `X-Forwarded-For` (Caddy перезаписывает заголовок, подделать нельзя — проверено). Лимит входа ученика — 120 запросов/мин с адреса: школа часто выходит в сеть через один адрес, а класс входит одновременно; PIN защищён ещё и блокировкой после 5 ошибок.

Безопасность: открыты только 22, 80, 443 (ufw). Секреты только в `backend/deploy/.env` на сервере, файл в `.gitignore`. `appsettings.Development.json` в образ не попадает. SQL-запросы в логах выключены (`Microsoft.EntityFrameworkCore.Database.Command: Warning`).
