# Пилот 26.11: сценарий и чек-лист

Цель (ТЗ, 11.1): за один урок с 5–10 школьниками 7–9 классов получить честные цифры для слайдов.

- **Рост глубины вопросов** — главная метрика: доля вопросов «вывести» и «оценить» в первых сессиях против последних.
- **Мини-диагностика** «до/после» (6 заданий PISA).
- **Опрос** учеников и учителя.

Порядок: входная проверка → 3–4 сессии «Обыграй ИИ» → итоговая проверка → опрос.

## 1. Что решить до пилота

| Вопрос | Варианты | Без этого |
|---|---|---|
| Где работает приложение | **Сервер** (`backend/deploy/README.md`) — HTTPS, работает и офлайн. Запасной — стек на ноутбуке (`docker compose`, `DOMAIN=localhost`) + HTTPS-туннель (например, Cloudflare Tunnel: `cloudflared tunnel --url https://localhost --no-tls-verify --http-host-header localhost`; этот вариант не проверялся — пробовать заранее). **Просто `http://<IP ноутбука>` не подойдёт**: без HTTPS браузер телефона не даёт `crypto.randomUUID` и `crypto.subtle` — не сохранятся вход и сессии | Пилот не провести |
| Ключ ИИ (Groq) | В `backend/deploy/.env` на сервере или `dotnet user-secrets` на ноутбуке | Вопросы получают только предварительную оценку (уровни ≤ 2) — **рост глубины не измерить** |
| Тексты | 4–6 опубликованных текстов на языке класса, сложность 1–3. Сейчас в репозитории только 4 примера: перенести библиотеку (`export-texts` / `import-texts`) или сгенерировать с ключом и прочитать | Ученикам нечего читать |
| Задания диагностики | Учитель читает `backend/Data/Diagnostics/forms.json`, носитель — казахскую версию | Риск ошибки в задании прямо на пилоте |
| Школа и учитель | Согласие школы/учителя на урок; ученики — только по имени, без фамилий | — |

## 2. Накануне (чек-лист)

- [ ] Сервер поднят, `https://<домен>/health` → `{"status":"ok"}`
- [ ] Ключ ИИ задан; один вопрос получает оценку ИИ, а не «Оценено правилами»
- [ ] Учитель зарегистрирован (настоящее имя), создан класс на нужном языке, код записан
- [ ] В классе опубликованы 4–6 текстов, учитель их прочитал
- [ ] Полный круг на одном телефоне тестовым учеником: вход → входная проверка → сессия → итог с оценкой ИИ → учитель видит ученика и вопросы. Потом тестового ученика **убрать из класса** (вкладка «Ученики» → «Убрать»)
- [ ] Офлайн: телефон в режим «самолёт» → приложение открывается, сессия проходит → сеть → оценки пришли
- [ ] Проверка сети с ноутбука: `node frontend/scripts/accept-net.mjs …` (ТЗ, раздел 17)
- [ ] Карточки с кодом класса и коротким «как войти» (по одной на парту)
- [ ] Опрос распечатан (раздел 6) или сделан в Google Forms
- [ ] Телефоны заряжены, есть 2–3 запасных устройства и мобильная точка доступа
- [ ] Сценарий видео: кто снимает, что (экраны, руки, без лиц детей без согласия родителей)

## 3. Роли команды

| Роль | Что делает |
|---|---|
| Ведущий | Объясняет, держит время, не подсказывает ответы |
| Техподдержка | Вход, PIN, зависшие телефоны; следит за панелью учителя |
| Наблюдатель | Записывает: где застревают, сколько минут на сессию, цитаты учеников |
| Видео | Демо «самолёт → сессия → сеть → оценки», экраны учителя |

## 4. Урок (~70 минут)

| Минуты | Что | Кто следит |
|---|---|---|
| 0–5 | Знакомство: «Сегодня вы будете задавать вопросы к текстам — и обыгрывать ИИ. Чем глубже вопрос, тем больше очков. Это не контрольная» | Ведущий |
| 5–10 | Вход: «Я ученик» → код класса → «я новенький» → имя (без фамилии; при совпадении — первая буква фамилии) → придумать PIN. Двое на одном телефоне — можно: второй выбирает «Другой ученик» | Техподдержка |
| 10–20 | **Входная проверка** — открывается сама перед текстами. Не помогать с ответами | Ведущий |
| 20–55 | **3–4 сессии**: прочитать текст → 3 вопроса → вывод → итог. Можно перечитывать текст и брать подсказку. Показать «лестницу» уровней на первом тексте, дальше — сами | Все |
| 55–57 | Учитель: класс → «Навыки» → **«Открыть итоговую проверку классу»** | Учитель |
| 57–67 | **Итоговая проверка** — карточка сверху на главной | Ведущий |
| 67–75 | Опрос (раздел 6), вопросы учителю | Наблюдатель |

Во время сессий учитель открывает «Навыки» и показывает классу, как растут уровни. Это хороший кадр для видео.

## 5. Если что-то пошло не так

| Что | Что делать |
|---|---|
| Пропал интернет | Ничего: сессии сохраняются на телефоне с предварительной оценкой и уйдут сами, когда сеть появится. Чтобы отправить сразу — открыть итог и нажать «Отправить сейчас» |
| Оценка ИИ долго не приходит | Итог показывает «Предварительно». Продолжать; оценка придёт при следующей отправке |
| Ученик забыл PIN или заблокирован (5 ошибок) | Учитель: «Ученики» → «Новый PIN» → продиктовать |
| Ученик выбрал не своё имя | «Это не я» → назад к списку |
| Зашёл не в тот класс | Учитель: «Убрать» → ученик вводит правильный код |
| Входная проверка не появилась | Её нет, если у ученика уже есть сессии. Не страшно: его рост глубины всё равно посчитается |
| Казахский интерфейс | Переключатель ҚАЗ/РУС вверху; для казахского класса включается сам |

## 6. Опрос

Анонимный, на бумаге или в Google Forms. Шкала 1–5: 1 — совсем нет, 5 — очень.

**Ученикам (рус.)**

1. Было интересно задавать вопросы к текстам? (1–5)
2. Было понятно, что нужно делать? (1–5)
3. Стало понятнее, как задавать «глубокие» вопросы? (1–5)
4. Хотел(а) бы заниматься так ещё? (да / нет / не знаю)
5. Что понравилось больше всего?
6. Что мешало или было непонятно?

**Оқушыларға (қаз.)**

1. Мәтіндерге сұрақ қою қызық болды ма? (1–5)
2. Не істеу керек екені түсінікті болды ма? (1–5)
3. «Терең» сұрақ қоюды түсіндің бе? (1–5)
4. Осылай тағы жаттыққың келе ме? (иә / жоқ / білмеймін)
5. Саған ең қатты не ұнады?
6. Не кедергі болды немесе не түсініксіз болды?

**Учителю**

1. Использовали бы вы это на уроках? Как часто?
2. Помогла ли карта навыков понять класс? Чего в ней не хватает?
3. Согласны ли вы с оценками ИИ? Где он ошибался?
4. Сколько времени у вас заняла подготовка (тексты, класс)?

Казахскую версию опроса показать носителю языка вместе с интерфейсом.

## 7. После пилота: цифры для слайдов

1. Дождаться, пока все сессии получат оценку ИИ: открыть приложение на телефонах учеников с интернетом.
2. Отчёт (на сервере — через `docker compose run --rm api pilot-report …`):

   ```bash
   cd backend
   dotnet run -- pilot-report 8A-1234 --since 2026-11-26
   ```

   Отчёт печатается в markdown: участие, уровни вопросов, рост глубины по ученикам и вместе, диагностика «до/после» и по навыкам, готовые формулировки для слайда. Имена скрыты («Ученик 1»); `--names` — показать (только для команды).
3. Сохранить отчёт в `docs/pilot-2026-11-26.md` **без** `--names`.
4. Свести опрос: средние по вопросам 1–3, доля «да» в вопросе 4, 3–5 цитат.
5. Скриншоты для слайдов: «Навыки» учителя, итог сессии с комментарием ИИ, режим «самолёт».

Как говорить о результатах:

- Всегда называть число учеников и длительность: «8 школьников, один урок».
- Рост глубины за один урок — это эффект тренажёра, а не доказанный рост грамотности. Диагностика за один день может не вырасти; если выросла — «первые признаки».
- Цифры демо-класса «8А (демо)» на слайды не берём: они синтетические. Отчёт по нему сам об этом предупреждает.
